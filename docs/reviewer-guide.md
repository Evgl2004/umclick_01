# Инструкция для проверяющего пользователя

Состояние после локальной реализации этапа В. Клиент и сервер используют строковый UUID, ролевые токены и схему состояния 2; точный договор приведён в [контракте В](block-1-stage-v-api.md). Публичный стенд ещё не обновлён, поэтому перед пользовательской приёмкой администратор должен подтвердить фактически развёрнутую версию.

Эта инструкция нужна для первого прохода по MVP umclick после развёртывания на сервере. Интерфейс уже работает, но некоторые элементы пока выглядят технически, поэтому лучше идти по сценарию ниже.

## Что подготовить

Администратор стенда должен выдать проверяющему:

- публичный URL стенда, например `http://203.0.113.10`;
- код регистрации преподавателя, если в `.env.demo` задан `TEACHER_SIGNUP_CODE`;
- тестовый телефон участника, можно использовать вымышленный номер;
- второй браузер, вкладку инкогнито или телефон для проверки роли участника.

## Роль преподавателя

1. Открыть публичный URL стенда.
2. В правом верхнем углу оставить язык `RU`. Русский язык включён по умолчанию.
3. В нижней навигации открыть вкладку `Преподаватель`.
4. Блок `Технические настройки` не открывать, если стенд работает. Там находится адрес API для диагностики.
5. В блоке входа указать логин, пароль и код регистрации преподавателя.
6. Нажать `Зарегистрироваться`. Если пользователь уже создан, нажать `Войти`.
7. После входа откроется рабочий кабинет преподавателя.
8. В блоке конструктора викторины заполнить `Название викторины`.
9. Заполнить текст вопроса и лимит времени.
10. Заполнить варианты ответов.
11. Отметить правильный вариант круглым переключателем слева от ответа.
12. При необходимости добавить ещё вопрос через `Добавить вопрос`.
13. Нажать `Сохранить новую`.
14. Если список викторин не обновился, нажать `Обновить список`.
15. Убедиться, что нужная викторина выбрана для live-сессии.
16. Нажать `Создать сессию`.

После создания сессии появятся PIN, QR-код и ссылка входа участника.

## Роль участника

Есть два удобных способа подключения.

Способ 1: через QR или ссылку:

1. Открыть QR-код с экрана преподавателя на телефоне или скопировать ссылку входа.
2. Участник попадёт на страницу `/join`.
3. PIN вводить не нужно, если вход выполнен по QR или token-ссылке.
4. Нажать `Предпросмотр сессии`, если preview не загрузился автоматически.
5. Ввести имя.
6. При желании ввести телефон и явно отметить согласие; оба поля необязательны для анонимного входа.
7. Нажать `Войти в сессию`.

Способ 2: через PIN:

1. Открыть публичный URL стенда во втором браузере или на телефоне.
2. В нижней навигации открыть вкладку `Участник`.
3. Ввести PIN с экрана преподавателя.
4. Нажать `Предпросмотр сессии`.
5. Ввести имя; телефон и согласие добавить при желании.
6. Нажать `Войти в сессию`.

## Проведение викторины

На экране преподавателя:

1. Нажать `Старт`: регистрация закрывается, но первый вопрос ещё не открывается.
2. В закрытом лобби нажать отдельную кнопку `Начать викторину`, чтобы начать зачитывание первого вопроса.
3. Дождаться фазы ответа. Участники могут менять выбор до закрытия окна ответа; счётчик отображается в live-блоке.
4. При необходимости только в фазе ответа нажать `Завершить приём ответов досрочно`: команда закрывает основное окно, но сохраняет обязательные 3 секунды доставки; правильность раскрывается только после них. В фазе доставки кнопок перехода нет.
5. Из фазы результатов нажать `Следующий вопрос`, если вопрос ещё есть. После последнего вопроса этой кнопки нет, сессия завершается естественно.
6. Для показа использовать `Экран демонстрации`. Повторное открытие использует действующую выдачу; `Отозвать доступ показа` закрывает именно её, после чего для нового окна нужна новая выдача.
7. Нажать `Рейтинг`, чтобы посмотреть таблицу лидеров без баллов. При общем третьем месте на пьедестале видны все участники с местом не больше трёх.
8. Нажать `Экспорт CSV`, чтобы скачать те же место, число правильных ответов и сумму времени правильных ответов в миллисекундах.
9. `Завершить` использовать только для принудительной остановки; результатом будет статус `aborted`.

На экране участника:

1. Дождаться вопроса.
2. Нажать один из крупных вариантов ответа.
3. До закрытия окна можно выбрать другой вариант; интерфейс отправляет новое намерение последовательно.
4. Дождаться раскрытия результата после основной фазы и трёхсекундной доставки.
5. Перейти к следующему вопросу, когда преподаватель нажмёт `Следующий вопрос` или завершится таймер результатов.

## Что проверить

- Преподаватель может зарегистрироваться и войти.
- Викторина создаётся и сохраняется.
- Live-сессия создаёт PIN, QR и ссылку.
- Участник подключается по QR/token-ссылке.
- Участник подключается по PIN.
- Вход только по имени работает; телефон и согласие необязательны.
- Участник может изменить выбор, но до результатов не видит правильность.
- Таймер вопроса работает.
- `Завершить приём ответов досрочно` доступно только во время ответов, сначала открывает трёхсекундную доставку, затем результаты.
- Истечение короткого JWT при действительном refresh-токене не требует ручного обновления страницы преподавателя: доступ обновляется, а WebSocket пересоздаётся.
- Выданный Display-доступ можно адресно отозвать, после чего старое окно больше не получает состояние.
- `Рейтинг` показывает место, число правильных ответов и точное время без баллов.
- `Экспорт CSV` скачивает согласованные с интерфейсом поля.
- Естественный финал имеет статус `finished`, кнопка `Завершить` — `aborted`.
- Обновление страницы участника и показа восстанавливает доступ, если токен ранее был успешно получен и сохранён.

## Известные ограничения MVP

- Интерфейс ещё не финальный и местами похож на техническую панель.
- Нет полноценной админки для управления преподавателями.
- Нет восстановления пароля.
- Нет HTTPS в demo compose без дополнительного reverse proxy.
- Для публичной проверки лучше использовать тестовые персональные данные.
- Часть ошибок API пока может отображаться техническим текстом.
