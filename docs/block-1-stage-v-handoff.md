## Реализованное поведение

### Backend и Redis

- `state_conflict` отделён от обычного `conflict`; только первый обязательно содержит актуальный `state`.
- Ролевые причины `access_required`, `access_malformed`, `access_scope_mismatch`, `access_invalid`, `access_revoked`, `access_expired` структурированы. Клиент удаляет токен только по трём последним однозначным причинам.
- Нормализация логина совпадает с фактической аутентификацией. Адрес из proxy-заголовков принимается только от настроенного доверенного peer.
- Lua использует 60 000 единиц на операцию, Redis `TIME`, `max(0, elapsed)`, `max(stored_last_ms, now_ms)` и одно атомарное решение по всем ключам. При отказе обязательного хранилища операция получает 503 и не выполняется.
- HTTP- и WebSocket-ограничители одного процесса повторно используют один Redis-клиент и пул на точный URL. Разные URL и внедрённые тестовые клиенты изолированы; Redis является прямой зависимостью backend.
- Снимок собственного ответа участника содержит монотонное `answer_version` по попыткам конкретного запуска. Путь ответа не получил общей блокировки строки сессии.
- Маршрутные квоты и точные значения приведены в [контракте В](block-1-stage-v-api.md).

### WebSocket

- До подтверждения доступа данные не отправляются; timeout авторизации — 10 секунд.
- Реализованы открытие 10/с с запасом 60, пределы 3/120/240, сообщение 16 КиБ, сообщения 5/с с запасом 20, аренда 15/45 секунд.
- Лишнее новое соединение отклоняется без вытеснения существующих. Redis-вызовы используют атомарные Lua-операции и собственное время.
- Полная ежесекундная сборка состояния удалена. Фоновая ревалидация выполняется через 45–75 секунд одним SQL-запросом; Redis heartbeat SQL не создаёт. Перед каждым игровым событием выполняется полная немедленная проверка.
- Flutter различает терминальные коды, 4429, 4503 и сетевой разрыв. Некорректный UUID проверяется до открытия; для отказа маршрутизации до `accept()` JSON `connection_error` не обещается.
- Истечение короткого JWT преподавателя с действительным refresh-токеном запускает общее однократное обновление доступа и новое соединение с точным новым токеном. Остальные терминальные причины 4003 не повторяются.

### Flutter

- Все маршруты сессии принимают строковый UUID; схемы `Bearer`, `Participant`, `Display` разделены.
- Сохранённый токен индексируется по роли, UUID и доверенному origin, не по внешнему IP; Display дополнительно разделён по UUID выдачи. Query-параметр `api` в join/display-сценарии игнорируется; секреты в URL не передаются.
- Редуктор принимает только схему 2, ожидаемый UUID и монотонную ревизию. При равной ревизии два счётчика не уменьшаются; после снятия локального наложения меньший `answer_version` того же запуска сохраняет целиком новый блок ответа, не мешая обновлению остальных допустимых полей. Финальный серверный ответ приоритетен, новый запуск очищает прежний выбор и принимает версию 0.
- Команды повторяют тот же `command_id`; ответы — тот же `submission_id`. Повторы ограничены тремя, для HTTP 503 каждый раз соблюдается серверный `Retry-After` 3 секунды. Обычный запрос ограничен 10 секундами, CSV — 30; новое намерение отменяет транспорт, а поздний результат не меняет интерфейс.
- 200 ответа остаётся нейтральным; правильность раскрывается только в разрешённой фазе. Участник может менять выбор до закрытия окна.
- `Старт` только закрывает лобби, а `Начать викторину` запускает первый вопрос. Досрочное завершение доступно только в `answering`, в `delivery` переходов нет, следующий вопрос доступен только из результатов при его наличии. Варианты участника нажимаются только в `answering` до истечения основного времени; первый и последующие такты таймера `delivery` блокировку не снимают. Анонимному участнику достаточно имени.
- Показ использует собственный сохранённый Display-токен и точный `grant_id`; преподаватель может идемпотентно отозвать выдачу, а новая выдача атомарно отзывает старую. Рейтинг, история и CSV используют место, число правильных итогов и точную сумму миллисекунд без баллов; пьедестал включает все строки с `rank <= 3`.

### Nginx и обновление

- Пять точных входных маршрутов отделены от остальных не-`OPTIONS` `/api/**`; статические файлы и WebSocket не расходуют HTTP-зоны.
- Настроены независимые адресные и общие зоны входа/игры с `nodelay`. Только локальный 429 Nginx получает `Retry-After: 1`; upstream 429/503 не перехватываются.
- Compose публикует только frontend-порт; backend не имеет `ports`. Фактическая внешняя недоступность backend пока не доказана.
- Команда `stage_v_game_data` поддерживает read-only инвентаризацию, реальный транзакционный rollback-test и отдельно защищённый apply. Она сверяет фактический порт PostgreSQL наряду с базой, адресом и ролью; порт входит в отпечаток и предохранитель вместе с SHA-256. Обычный запуск и миграции очистку не вызывают.

## Ошибки, исправления и предупреждения

- Первый серверный прогон новых снимков выполнил 160 тестов: 157 успешных, 1 неуспешный и 2 пропущенных. Единственный старый точный словарь не ожидал обязательное `answer_version: 0`; после адресно разрешённой синхронизации полный набор прошёл.
- Перед финальной приёмкой красные регрессии подтвердили два клиентских дефекта: ролевые снимки откатывали выбор 22/версию 2 к 21/1 или `null`/0 после снятия локального наложения, а синхронный такт таймера давал `questionLocked=false` при восстановлении и переходе в `delivery`. После адресных исправлений 47/47 регрессий и полный набор 123/123 прошли. Первые два виджет-запуска дополнительно выявили только ошибки испытательной оболочки — Latin-1 для кириллического JSON и тесный тестовый viewport; после UTF-8 и тестового масштаба окончательный красный повтор падал ровно по фазовому условию.
- Первый итоговый Flutter-прогон после исправлений остановился до тестов на одном неформатированном файле виджет-теста. Штатное форматирование изменило только этот тест; повтор дал 69 файлов без изменений, анализ без замечаний, 116 тестов и web-сборку.
- Первый повтор нагрузки завершился полным cleanup, но получил 409 при досрочной команде: синтетическое окно 30 секунд могло истечь после 600 ответов и подготовительных операций. Только тестовый лимит увеличен до 120 секунд, перед командой добавлена явная проверка `answering`; повтор выполнил 600 ответов и завершился успешно.
- Простой `http.server` не поддержал прямое обновление SPA-маршрута `/join?...` и вернул 404 без изменения приложения или данных. Штатный Flutter web-server на том же origin подтвердил восстановление участия.
- Первая адресная очистка браузерного графа была отклонена контролем разрешений и не выполнялась; последующий объединённый backend получил два расхождения глобальных счётчиков. После отдельного разрешения повторная инвентаризация точной цели `127.0.0.1:5433`/`test_umclick_local`/`umclick_test` показала, что строки ID 34/33/32/33 и все проверенные зависимости уже отсутствуют. PostgreSQL не менялся; из точного Redis-пространства удалён один найденный собственный ключ, остаток 0. Повторный объединённый набор завершён кодом 0.
- Первая попытка Python через `backend/.venv/Scripts/python.exe` не создала процесс из-за привязки launcher к прежнему пути. Применён штатный bootstrap через Python pgAdmin; установка не выполнялась.
- Первый вариант нагрузки оставлял синтетические строки в постоянной `--keepdb`, из-за чего следующий backend-прогон дал 10 падений и 1 ошибку. Сценарий получил адресную транзакционную очистку; повтор и последующие 159 тестов успешны.
- Первый итоговый frontend и первый `check-all` в песочнице зависли на служебном Flutter lock и были остановлены с кодом 1. Те же штатные команды с ранее разрешённым доступом к установленному SDK завершились кодом 0.
- Первый финальный Redis-командный wrapper не разобрался PowerShell из-за двоеточия после переменной и не запустил тесты. Исправленная команда прошла.
- После полного Redis-прогона обнаружен 61 собственный Channels-ключ, не охваченный `tearDown()` двух адресных тестов. Точный namespace очищен `SCAN`/`DELETE` до 0; инструкция дополнена обязательным внешним `finally`.
- Первый поиск похожих на секреты значений завершился кодом 1 на двух строках `.env.demo.example`; адресная проверка доказала, что это только обязательные демонстрационные заглушки `change-this-*`. Повтор с явным разрешением этих заглушек завершился кодом 0.
- Первая объединённая статическая оболочка не разобралась PowerShell из-за двоеточия после имени переменной и не начала проверки. После исправления интерполяции перечень файлов, хвостовые пробелы и секреты проверены успешно.
- Две финальные читающие проверки окружения сначала остановились до результата: первая — на обязательном формате тестового Redis namespace, вторая — на ошибочно предположенном имени таблицы `accounts_user`. Исправленный ORM-запрос подтвердил чистую `test_umclick_local`; ни одна из этих попыток не изменяла данные или сервисы.
- Django предупреждает, что тестовая роль не подключается к служебной базе `postgres`; он использует первую настроенную тестовую базу. Защитная проверка подтверждает фактическую `test_umclick_local` и неадминистративную роль.
- Flutter сообщает о 15 более новых несовместимых с lock-файлом версиях пакетов, deprecated `--pwa-strategy` и успешном Wasm dry run. Зависимости не обновлялись.
- `git diff --check` выводит только ожидаемые предупреждения LF→CRLF.

## Остаточные риски и следующие разрешения

- Нужны отдельное разрешение и окно работ для стендовой ПР-40, обновления и внешней приёмки.
- На стенде требуется измерить и задать фактический `TRUSTED_PROXY_CIDRS`; предполагаемое значение не внесено.
- Требуются `nginx -t` в целевой среде, измерение реальных proxy-квот и проверка с независимого узла, что backend недоступен напрямую.
- Требуется полный мобильный браузерный прогон всех фаз: размер 390×844 пока проверен только в ожидании.
- Локальная нагрузка не измеряла CPU/RAM, отдельное время ожидания PostgreSQL-блокировок или устойчивость публичной инфраструктуры; SLO не установлен.
- Потерянный успешный ответ первичной выдачи токена участия/показа не восстанавливается: сервер хранит только отпечаток, а идемпотентной выдачи нет.
- Реализация версий и архивирования — отдельная последующая задача после приёмки В.
