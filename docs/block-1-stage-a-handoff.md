## Исправление после независимого контроля

1 сентября 2026 года воспроизведён и устранён блокирующий обход защиты истории. `LiveSession.save()` и `SessionParticipant.save()` определяли создание по `self._state.adding`; новый объект Python с первичным ключом существующей строки попадал в ветку создания, хотя Django выполнял обновление строки. По той же причине дополнительно исправлен `SessionDisplayAccess.save()` с явно переданным существующим UUID.

Изменены `backend/apps/session/models.py`, `backend/apps/session/tests/test_stage_a.py` и этот отчёт. Схема базы не менялась, новая миграция не создавалась. Каждое сохранение теперь выполняется в транзакции: при заданном ключе фактическая строка ищется с `select_for_update()`, найденная строка проходит правила изменения и явный `UPDATE`, отсутствующая — правила создания и явный `INSERT`. Для существующего участия любое изменение возвращает `HistoryConflict`; завершённую или остановленную сессию открыть либо перенести на другую викторину нельзя. Аналогичная проверка защищает неизменяемые поля доступа показа, сохраняя разрешённый однократный отзыв.

Добавлены постоянные тесты:

- `test_new_instance_with_existing_pk_cannot_reopen_finished_session`;
- `test_new_instance_with_existing_pk_cannot_replace_session_quiz`;
- `test_new_instance_with_existing_pk_cannot_move_participation`;
- `test_new_instance_with_existing_pk_cannot_replace_participation_identity`;
- `test_each_rejected_replacement_preserves_all_linked_history`;
- `test_normal_session_and_participation_creation_still_work`;
- `test_allowed_unfinished_session_transitions_still_work`;
- `test_new_instance_with_existing_uuid_cannot_replace_display_access`.

Целевой класс: 14 тестов за 1,025 секунды, все успешны. Исходный независимый сценарий из `.codex_work/stage-a-review/check_history.py`, ранее воспроизводивший три подмены, после исправления прошёл 3 из 3 проверок. Итоговый штатный прогон: **68 тестов за 20,403 секунды, все успешны, пропусков нет; код завершения 0**. `No changes detected`, системная проверка Django и `git diff --check` — без замечаний. Временные базы удалены. Частный PostgreSQL 17 из `.codex_work/postgres-stage-a` корректно остановлен через `pg_ctl`; стенд не использовался.

## Передача Б и В

- Б получает защищённые модели и точки доступа. Прежний подсчёт и перезаписываемый итоговый ответ пока сохранены; журнал попыток, новый рейтинг, окно доставки, окончательная финализация и версии команд не реализованы в А.
- В получает точные заголовки, UUID-маршруты и первое сообщение соединения. Старый Flutter-клиент пока несовместим; его сборка, хранение токенов, обновление страницы, ограничения 429/503, нагрузочные и сквозные проверки не выполнялись.
- Версионирование и архивирование обязательны позднее. Сейчас использованное содержимое нельзя редактировать; это сознательное ограничение при сохранении прежних результатов.
- Перед обновлением нужна отдельно разрешённая подготовка только согласованных тестовых игровых данных на старой схеме, резервная копия и проверка её восстановления. Неподготовленные записи остановят миграцию, а не получат выдуманного владельца. Роли существующих учётных записей проверяются и назначаются явно; пользовательские пароли не меняются.
- Проверены PostgreSQL 17 и канал событий в памяти. PostgreSQL 16 из состава развёртывания, реальный Redis/несколько процессов, HTTP/HTTPS стенда и весь блок не приняты этим прогоном.
