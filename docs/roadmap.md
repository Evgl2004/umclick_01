# Дорожная карта umclick

Актуально на 15 мая 2026.

## Где мы сейчас

Мы на этапе расширенного MVP. Базовый сценарий уже собран: преподаватель может создать викторину, запустить live-сессию, показать QR/ссылку входа, участники могут быстро зарегистрироваться и отвечать на вопросы, результаты считаются и экспортируются.

## Уже сделано

- Базовая инфраструктура проекта: Django + DRF, Flutter Web, PostgreSQL, Redis, Celery, Docker Compose.
- Ветки `main` и `develop-cai`, разработка ведется в `develop-cai`.
- Регистрация и JWT-вход преподавателя.
- CRUD викторин для преподавателя.
- Визуальный конструктор викторин во Flutter.
- Создание live-сессий с PIN, QR и `join_token`.
- Подключение участника по PIN или по ссылке `/join?token=...`.
- Предпросмотр сессии до регистрации участника.
- Быстрая регистрация участника: телефон, имя, согласие.
- Версионирование согласий и публичные legal-страницы.
- WebSocket-события для live-сессий.
- Управление раундом: старт, следующий вопрос, раскрытие ответов, завершение.
- Таймер вопроса и авто-раскрытие через Redis + Celery beat.
- Kahoot-style скоринг по скорости ответа.
- Leaderboard и CSV-экспорт результатов.
- Первый слой локализации интерфейса: русский по умолчанию, переключатель RU/EN, сохранение выбора языка.
- Инфраструктура языка и первый каталог строк вынесены во Flutter-модуль `frontend/lib/l10n`.
- Основные, динамические и legal-строки интерфейса вынесены из `main.dart` в каталог переводов.
- Первые пользовательские подсказки в интерфейсе.

## Что важно улучшить дальше

- Полноценная дизайн-система в стиле игрового квиза: более яркий экран участника, крупные варианты ответов, цветовые зоны, динамика раунда.
- Полная локализация всех сообщений, включая ошибки API и live-события.
- Переход с текущего каталога строк на полноценную Flutter `l10n`/ARB-схему.
- Разделение большого `frontend/lib/main.dart` на модули: API, локализация, teacher UI, participant UI, legal pages.
- Тесты backend API: join по token/PIN, preview, ответы, таймер, экспорт.
- Frontend smoke-тесты ключевых сценариев.
- Улучшение безопасности персональных данных: политика хранения, удаление/анонимизация, аудит доступа.
- Роли и управление преподавателями.
- Импорт/экспорт викторин.
- Более удобная аналитика по результатам сессии.

## Ближайшие шаги

1. Переработать экран участника под более узнаваемый Kahoot-like UX.
2. Переработать панель преподавателя под сценарий live-ведения урока.
3. Перейти с текущего словаря строк на Flutter `l10n`/ARB.
4. Добавить backend-тесты на публичные endpoints и join-flow.
5. Добавить smoke-проверку Flutter Web через контейнер или CI.

## Принципы разработки

- Маленькие, проверяемые изменения.
- Отдельный коммит на логически завершенный шаг.
- Русские сообщения коммитов.
- Сначала сохраняем рабочий MVP, затем улучшаем архитектуру.
- Изменения в UI делаем вместе с понятными состояниями: загрузка, ошибка, пустой список, успешный результат.
- Все, что касается персональных данных, делаем явно и версионируемо.
