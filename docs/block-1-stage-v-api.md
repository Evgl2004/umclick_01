# Контракт этапа В «Интерфейсы, нагрузка и завершение первого блока»

Версия документа: 1.0. Фактическая локальная реализация от 4 сентября 2026 года.

Документ дополняет [контракт данных и доступа А](block-1-stage-a-api.md) и [контракт проведения Б](block-1-stage-b-api.md). PostgreSQL остаётся единственным источником игровых данных. Redis используется только для общих квот, WebSocket-аренд и Channels; ответы, итоги, результаты и история в Redis не переносятся.

Версии, черновики и архивирование викторин в этап В не входят. Их согласованная будущая модель описана отдельно в [документе версий и архивирования](quiz-versioning-and-archiving.md).

## HTTP-ошибки

| Ситуация | Статус и тело | Действие клиента |
|---|---|---|
| Обычный конфликт подключения, ответа, рейтинга или другой операции | `409`, `code: conflict`, `detail`; `state` не гарантируется | Не повторять операцию; выполнить не более одного разрешённого чтения актуального состояния |
| Прикладная квота | `429`, `code: rate_limited`, целый `retry_after`; тот же `Retry-After` в заголовке | Ограниченный повтор с прежним идентификатором операции |
| Недоступность обязательного ограничителя | `503`, `code: limiter_unavailable`, `retry_after: 3`; `Retry-After: 3` | Операция не выполняется; допускается ограниченный повтор |

## Общий алгоритм Redis

Одна операция стоит 60 000 целых единиц. Скорость задаётся целым числом единиц на миллисекунду; например, 10 запросов в минуту пополняют 10 единиц/мс, а 10 запросов в секунду — 600 единиц/мс.

Каждый Lua-вызов получает время только через Redis `TIME` и для каждого ключа вычисляет:

```text
elapsed_ms = max(0, now_ms - stored_last_ms)
tokens = min(capacity, tokens + elapsed_ms * refill_per_ms)
new_last_ms = max(stored_last_ms, now_ms)
```

Все затрагиваемые запасы проверяются одним атомарным `EVAL`. Если хотя бы одного недостаточно, списание не выполняется ни из одного; `retry_after` округляется вверх до целой секунды. Будущая `stored_last_ms` сохраняется, поэтому управляемая проверка 40/41 не получает случайного пополнения. Сырые логины, IP и токены заменяются HMAC-отпечатками в ключах. Локального резервного счётчика при отказе Redis нет.
